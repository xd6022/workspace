# 02 — 蒸馏技术详解

## 蒸馏技术全景图

```
知识蒸馏
├── 响应蒸馏（Response-based）     ← Hinton 经典方法
│   └── 只用 Teacher 的最终输出（logits）
│
├── 特征蒸馏（Feature-based）       ← 中间层对齐
│   └── 对齐 Teacher 和 Student 的中间层表示
│
├── 关系蒸馏（Relation-based）      ← 样本间关系
│   └── 保持 Teacher 输出的样本间相对关系
│
└── 数据蒸馏（Data Distillation）   ← 生成/合成数据
    └── 用 Teacher 生成训练数据，再训练 Student
```

---

## 一、响应蒸馏（Response-based KD）

### 经典方法：Hinton KD

就是 [01-模型蒸馏基础](./01-模型蒸馏基础.md) 里讲的，用 Teacher 的 logits 做软标签。

```python
# 伪代码
teacher_logits = teacher_model(input)  # 冻结，不计算梯度
student_logits = student_model(input)

soft_loss = KL_div(
    softmax(teacher_logits / T),
    softmax(student_logits / T)
) * T * T

hard_loss = CrossEntropy(student_logits, labels)
total_loss = alpha * hard_loss + (1 - alpha) * soft_loss
```

### 适用场景
- ✅ LLM 蒸馏的最常用方式
- ✅ 输出空间明确的任务（分类、QA、翻译）
- ⚠️ 生成任务需要额外处理（用 Teacher 逐 token 指导）

---

## 二、特征蒸馏（Feature-based KD）

### 核心思想

不仅用 Teacher 的输出，还对齐中间层的特征表示。

```
Teacher:  输入 → [Layer1] → [Layer2] → ... → [LayerN] → 输出
                        ↓ 对齐      ↓ 对齐
Student:  输入 → [Layer1] → [Layer2] → ... → [LayerM] → 输出
```

### 代表方法

| 方法 | 论文 | 核心思路 |
|------|------|---------|
| FitNet | *FitNets: Hints for Thin Deep Nets* (2015) | 用 Teacher 中间层作为"提示"（hints） |
| AT | *Attention Transfer* (2017) | 对齐 Attention Map |
| FSP | *A Gift from Knowledge Distillation* (2017) | 保持层间关系矩阵 |
| LSTM | 用于 NLP | 对齐隐藏状态 |

### 代码示意

```python
# 特征蒸馏损失
def feature_loss(student_feat, teacher_feat):
    # 需要先做维度对齐（投影层）
    proj = nn.Linear(student_dim, teacher_dim)
    student_projected = proj(student_feat)
    return MSE(student_projected, teacher_feat)
```

### 适用场景
- ✅ Teacher 和 Student 结构相似（同架构缩小版）
- ✅ 需要深层知识迁移
- ❌ Teacher/Student 架构差异大时需要适配层

## 三、关系蒸馏（Relation-based KD）

### 核心思想

不是对齐单个样本的输出，而是保持**样本之间的关系**。

```
Teacher 眼里：样本 A 和 B 很相似 → Student 眼里：A 和 B 也应该很相似
```

### 代表方法

| 方法 | 核心思路 |
|------|---------|
| RKD (*Relational KD*) | 保持样本对之间的欧氏距离和角度 |
| PKT (*Probabilistic KD*) | 用概率分布建模样本间关系 |
| CCKD (*Correlation Congruence*) | 保持特征通道间的相关性 |

### 适用场景
- ✅ 度量学习、检索任务
- ✅ 需要保持样本空间结构

## 四、针对 LLM 的蒸馏方法

这才是我们的主战场！以下是专门针对大语言模型的蒸馏技术：

### 4.1 数据级蒸馏：Self-Instruct / Evol-Instruct 路线

```
流程:
1. 用 Teacher（如 GPT-4/Claude）生成大量指令-回答对
2. 筛选/清洗生成的数据
3. 用这些数据做 SFT 微调 Student

这是目前最主流的方式！
```

**关键项目**：
- **Alpaca**：用 GPT-3.5 生成 52K 指令数据，微调 LLaMA 7B
- **Vicuna**：用 ShareGPT 对话数据微调 LLaMA
- **WizardLM**：Evol-Instruct 自动化指令进化
- **Orca**：用 GPT-4 的推理过程（Chain-of-Thought）做蒸馏

### 4.2 输出级蒸馏：Logit Distillation

直接对齐 Teacher 和 Student 在每个 token 位置的输出分布。

```python
# Token 级别的蒸馏
for teacher_logit, student_logit in zip(teacher_outputs, student_outputs):
    loss += KL_div(
        softmax(teacher_logit / T),
        softmax(student_logit / T)
    )
```

**代表项目**：
- **DistilBERT**：BERT → DistilBERT（小 40%，保持 97% 性能）
- **TinyBERT**：两阶段蒸馏（通用 + 任务特定）
- **MiniLLM**：用逆向 KL 散度的蒸馏方法

### 4.3 混合方法：Orca 风格

Orca 系列的核心创新：

```
不只是让 Student 学"答案是什么"
还让 Student 学"Teacher 是怎么推理出答案的"

数据包含：
├── System prompt（角色定义）
├── User query（用户问题）
├── Teacher's step-by-step reasoning（推理过程）⭐ 关键
└── Final answer（最终答案）
```

## 五、蒸馏方法选择决策树

```
你的场景是什么？
│
├── 有大量领域标注数据？
│   └── 是 → 输出级蒸馏 + SFT（质量最高）
│   └── 否 → ↓
│
├── 能调用大模型 API（GPT-4/Claude）？
│   ├── 是 → 数据蒸馏：Teacher 生成数据 → SFT Student
│   └── 否 → ↓
│
├── Teacher 和 Student 同架构？
│   ├── 是 → 特征蒸馏 + 响应蒸馏
│   └── 否 → 纯响应蒸馏
│
└── 对生成质量要求极高？
    └── Orca 风格：让 Student 学习推理过程
```

## 六、针对 RF4 7B 蒸馏的推荐方案

结合我们的目标：

```
方案：混合蒸馏

第1步：数据蒸馏（主力）
├── 用 GPT-4/Claude/DeepSeek 等大模型
├── 生成 5000-20000 条 RF4 相关 QA 对
├── 包含推理过程（Orca 风格）
└── 覆盖：钓点、鱼种、装备、机制、技巧

第2步：SFT 微调（数据驱动）
├── Base Model: Qwen2.5-7B / LLaMA-3-8B / Mistral-7B
├── 用第1步生成的数据做指令微调
└── LoRA 高效微调（省显存）

第3步（可选）：强化蒸馏
├── 如果能拿到 Teacher 的 logits
├── 加入输出级蒸馏损失
└── 进一步提升质量
```

## 七、补充：Recent Advances

### GKD（Generalized Knowledge Distillation, 2022）
- 在训练时动态生成软标签（on-policy）
- 不需要提前跑完所有数据

### DKD（Decoupled Knowledge Distillation, 2022）
- 将蒸馏拆分为 Target Class KD 和 Non-Target Class KD
- 解决传统 KD 在非目标类别上的信息稀释问题

### Distil-Whisper（2023）
- Whisper → Distil-Whisper 的音频模型蒸馏
- 证明数据蒸馏 + 输出蒸馏组合在生成模型中有效

### DeepSeek 系列
- DeepSeek-V2/V3 使用了蒸馏技术
- MoE（混合专家）架构中的知识迁移
